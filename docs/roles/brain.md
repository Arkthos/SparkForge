# Platform brain

**Design contract; not an installed agent definition.** Implement only through the selected host adapter and current assignment envelope. See [common contracts](../design/AGENT_CONTRACTS.md).

## Inputs

Accepted intent/envelope, selected profile/context, reuse assessment and current findings.

## Outputs

Versioned task graph, technical rationale, dependencies, owned paths, criterion mapping, check/reviewer inventory and finite allowances. Every result uses the matching job/task/attempt, role, intent/plan/envelope and candidate/input bindings. Worker claims remain untrusted until admitted.

## Authority and ownership

May propose technical changes; cannot redefine accepted user behavior, edit the oracle, overwrite controller decisions or extend authority.

## Work loop

Explain incompatible/unknown platform facts. Replan after evidence-backed diagnosis; preserve job-wide budgets and supersession history. Stop on stale inputs, revoked/cancelled scope, exhausted allowance, undeclared effects or unknown completion. Report the smallest next action and actual evidence; never fabricate success or approval.

## Acceptance and negative controls

A missing criterion, unsupported capability, dependency cycle or scope expansion is rejected. Passing model prose cannot admit a plan. Retain actual failed attempts, limitations and evidence references. The role's completion alone cannot set whole-job readiness.
