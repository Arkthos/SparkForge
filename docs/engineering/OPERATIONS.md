# Operation and recovery guide

## Current assisted-v1 operation

Use the [native package README](../../plugins/sparkforge/README.md), [factory guide](NATIVE_FACTORY.md), [knowledge guide](NATIVE_KNOWLEDGE.md) and [exact spec format](../../plugins/sparkforge/references/SPEC_FORMAT.md). Those documents describe implemented commands. Existing manual decisions remain operator-owned. The helpers do not provide an autonomous scheduler or an OS sandbox.

## Coordinated target operation

The future coordinated CLI/host UX is not implemented; no runnable command is invented here. WP-153/WP-170 update this guide from actual behavior. The target operator should be able to:

1. Select one environment/profile and permitted sources/resources.
2. Describe the outcome, resolve material questions and inspect the accepted baseline/envelope.
3. Observe current tasks/roles, evidence, remaining allowance and controller/review findings.
4. Let ordinary bounded repair/replanning proceed; answer focused material decisions when needed.
5. Request cancellation or resume a saved job; see actual stopped/unknown effects before replay.
6. Inspect exact delivered code/docs/evidence and separately scoped contribution effects.

## Blocker explanations

| Observed situation | Expected next action |
|---|---|
| Missing source/platform fact | Retrieve selected authorized evidence or ask a consequential question; preserve NOT_ASSESSED |
| Check failure | Reproduce, classify cause and route bounded repair; do not discard the failure |
| Semantic drift | Controller cites baseline deviation; rework or request an explicit intent change |
| Required review missing/stale | Obtain current genuine inspection; never refresh a token onto an old opinion |
| Budget/no progress stop | Show used/remaining/unknown resources, repeated cause and concrete extension/narrowing options |
| Lost response/unknown completion | Inspect operation identity and actual effects; reconcile before retry |
| Cancel/revocation | Stop new admission; report whether already-started effects actually stopped |
| Unsupported host capability | Explain the gap and narrower support/explicit adapter options; no silent provider substitution |

## Local data and checkpoints

Keep real sources/profiles/journals/output within the selected boundary. Retain only selected useful diagnostics, use bounded summaries and do not commit raw traces. Checkpoints identify job/intent/plan/candidate and pending operations; restore/resume must recheck actual current state rather than trusting an old summary.

No production SLO/support contacts are declared yet. Those come from actual qualification and genuine owner commitments, not an invented template value.
