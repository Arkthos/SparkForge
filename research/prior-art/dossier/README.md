# Prior-art dossier: detailed public publication edition

**Edition:** 2026-11-12. **Underlying research:** 2026-11-05.

This is the detailed public-source counterpart to all **14** documents in the
original authored prior-art dossier. It expands the earlier
[short reference](../README.md), rather than treating that reference as a
complete publication of the research. It preserves public mechanisms,
alternatives, source identities, inspection limits, counterexamples, and
licensing questions in separate topical documents.

It is **not** a byte-for-byte copy of the original dossier. That dossier also
contained restricted contextual comparisons. Those portions, their private
source identities and operating details, and links into excluded collections
are withheld, not disguised under replacement organization names. The
document-by-document accounting below explains the boundary. Removing names
would not grant redistribution rights.

## What the public research establishes

Substantial prior art exists for specification, state, bounded agent loops,
testing, evaluation, relevant knowledge, and review. The most useful reuse unit
is often a contract, a small mechanism, a test pattern, or a carefully adapted
skill, not an entire competing framework.

The historical catalog contains **33 pinned public repositories** and **90
registered inspections across 88 source files**. Nine repositories received
selected implementation reading. The other reviews have narrower
documentation, specification, configuration, or skill-contract ceilings.
These are not 33 whole-repository audits. The source register retains all
10,471 distinct registered line coordinates, not copies of those source lines.

The ZazenCodes supplement separately preserves its timestamped analysis and
recorded review method: 778 unique available auto-caption segments and two
sampled frames. Neither the captions nor the frames nor the supplied overview
image is redistributed. Reading the original authored observations for this
edition is not a new viewing, continuous listening, or an independent rerun.

## Findings that change adoption decisions

1. **Instructions and enforced gates are different.** Spec Kit implements
   noninteractive pause and verdict handling; generic caller-supplied verdicts
   still need a trustworthy approval channel. RSC's digest identifies the
   accepted artifact but does not authenticate the person accepting it.
2. **Compatibility is route-specific.** RSC's historical host table excludes
   Copilot session memory. Agent Skills distinguishes skills from Claude-only
   commands. BMad Loop's bundled Copilot launch grants broad permissions and
   relies on a particular host observation. Waza's ordinary, text-only, and
   evidence-judge routes have different constraints.
3. **Local presentation does not establish local execution.** Foreman's
   selected sandbox code uses hosted Vercel Sandbox in local development too.
   Promptfoo separates target calls, generation, grading, telemetry, and hosted
   services; one switch is not a network boundary.
4. **An agent turn is not acceptance.** SSSF separates phase completion from
   final acceptance. Waza's evidence grader rejects missing or invalid
   verdicts rather than treating absence as approval.
5. **A pin is not a release claim.** The reviewed BMad main is v7 preview alpha,
   Spec Kitty main is a release-candidate line, and BMad Loop is early beta.
   The archived GSD link points to a different current repository.
6. **License scope matters.** API `NOASSERTION` can coexist with an actual MIT
   or Apache grant. 12-Factor Agents distinguishes code from written content.
   The Archon wrapper and ZazenCodes root/v1 have unresolved root reuse
   licensing; the latter's v2 GPLv3 grant is subtree-specific.
7. **Public sources do not supply private integration evidence.** Current
   approved sources, host permissions, component contracts, and deployment
   acceptance must be established separately. Missing comparison remains
   `NOT_ASSESSED`.

## How this edition is maintained

[Public source metadata](../sources.json) remains the identity and range
inventory. [Catalog analysis](catalog-analysis.json) supplies the original
public commentary for the two rendered reference views. Neither file is a
source-code mirror. [Public context sources](public-context-sources.json)
accounts for the practitioner articles, standards, videos, and discovery-only
references that are not interchangeable with those 33 repository snapshots.

The enclosing project's [current status](../../../docs/PROJECT_STATUS.md), not
the historical study's old planning state, determines what SparkForge implements
today. This edition selects no framework, installs nothing, runs no model or
candidate software, and grants no publication permission for excluded material.

The [outer inventory](../../publication-manifest.json) binds the publication
bytes and retains earlier check records. Follow the local validation recipe in
the [research library](../../README.md). Its result establishes document
integrity, not current upstream availability, redistribution clearance,
deployment acceptance, or a successful GitHub publication.
